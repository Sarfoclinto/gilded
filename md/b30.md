# B31 — Hub phase 1B: signing offline entries, and the review screen (web)

Needs B30 (server) in place first, with migration 0048 applied.

## What it does
- **Device key**: the first time someone is signed in on a device, it makes a signing key for them. The private half can never be copied out of the browser (non-extractable, kept in IndexedDB). The public half is sent to the server (`POST /sync/devices`) once a connection is there, and again only if the key changes. Works even if the first sign-in was offline: the key is made then, registered later.
- **Signing**: every purchase, payout, cash in/out and note exchange saved on the device is signed when it is saved (exact text agreed with the server). The signature is kept with the entry in the queue.
- **Sending**: signed entries go through `/sync/commands`, which applies them as the person who made them.
  - Applied: gone from the queue, as before.
  - Held or rejected (for example the day was closed in the meantime): kept by the server for a manager; leaves the queue; the person sees a red message saying a manager will review it.
  - Refused by the server (key not known, signature mismatch, permission): nothing was recorded, so the entry is sent the normal way, as before, and the server's normal answer applies. If the key was the problem it registers again.
  - No key yet: sent the normal way, exactly as before. Nothing about sending got riskier.
- **Offline entries screen** (menu: Review → Offline entries, needs `sync:review`): held and rejected entries with who made them, branch, when, what the server said; Try again (runs it again as the original person) and Dismiss (reason of 5+ characters). Last 20 dealt with are listed.
- "Forget this device" also removes the keys.

## Not in this step (decided on purpose)
Opening and closing the day while offline is **not** included. Everything after an opening needs the day's id, which only the server makes, so queuing it needs the screens to work from a locally-created day first. That is its own change and I will do it right after the next hub step rather than half-do it here.

# B30 — Hub phase 1A: offline sync on the server

Nothing changes on screen yet; this is the server half. The web half (signing commands, queueing open/close day, the Sync review screen) is B31.

## What it does
- **Device keys**: each device registers a public key for the signed-in person (`POST /sync/devices`). Commands made offline are signed with the private key, so the server can trust who made them even when the person is not signed in at sync time, and even when another computer (a branch hub) relays them.
- **Signed batch sync** (`POST /sync/commands`, up to 200, in order). For each command the API checks, in this order: the signature matches the registered key for that person+device; the person is still active; the person is allowed to do that kind of thing *now* (transaction.create → transactions:create; pay / movement / open / close → days:manage; note exchange → notes:exchange). If any check fails the command is **refused** (nothing recorded; the sender keeps it and shows why). Otherwise the database applies it as that person and records the result.
- **Reality wins**: a command is never silently lost. Result is one of
  - `applied` (flags: `offline` if over 2 minutes late, `very-late` over a day, `already-recorded`, `duplicate`),
  - `held`: something it depends on is missing or the state changed (day not there / closed, transaction void...) — kept with full content, may succeed on retry,
  - `rejected`: the entry itself breaks a rule (validation, payout mismatch...) — kept for a manager's decision.
  Sending the same command again returns the recorded result (safe resend).
- **Review** (`GET /sync/review`, `POST /sync/review/{id}` with retry | dismiss + note ≥ 5 chars), permission **sync:review** (Manager and Director). Retry runs the saved command again *as the person who made it* (the books show who really did it); dismiss needs a reason; both audited. Managers are notified when something is held or rejected.
- Existing business rules already cover some cases (a movement saved before the day closed lands in the open day and says so); this builds on them, nothing was loosened.
