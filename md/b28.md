# B29 — One company per installation (no company field, no address screen)

## Decisions recorded
- "Gilded" is the existing company's name, not the app's. Kept as the placeholder name everywhere for now (one place to change later per company: `desktop/assets/defaults.json` companyName; web titles are still the literal "Gilded").
- For now every company gets **its own frontend + backend (+ database)**. The database stays multi-company-capable underneath, so shared hosting later needs no rewrite; it is just not used.

## What changes
- **Login**: the Company field and "Sign in to a different company" are gone. The server uses the company it was deployed for (`COMPANY_SLUG` in deploy/.env, as before).
- **Offline sign-in**: people are now known by username alone (no company in the key). Anyone who used the earlier test build must sign in once online again.
- **Desktop app**: the "enter your server address" screen is gone. Each company's installer has its server built in (`desktop/assets/defaults.json`: companyName, serverUrl, channel). On every start a small **landing page** shows the company name and checks the connection (Connected / No connection, with a note), then opens the app by itself; with no connection it opens within about two seconds from the stored data. A copy built without a server shows "This copy is not set up yet".
- Removed: *Change server address* (menu and My settings). Server address changes = a new build.
- Removed: the stored-copy wipe when a different company signs in (no longer possible).

## "What is the server address?"
The **backend** address: whatever answers `/api/v1/...` and `/health/live`. In production Caddy serves website and API on one address, so it is just the company's web address (https://gilded.yourcompany.com). In dev: backend `http://localhost:5080` (not the Vite page server `localhost:5173`). Dev run: `GILDED_SERVER_URL=http://localhost:5080 npm run start -w @gold/desktop`.

## Files
Deleted: web/src/features/auth/company.ts, desktop/assets/setup.html
New: desktop/assets/landing.html
Changed: web/src/features/auth/{offlineLogin.ts,offlineLogin.test.ts,hooks.ts,store.ts,schemas.ts,pages/LoginPage.tsx}, web/src/shared/platform/platform.ts, web/src/features/settings/DesktopRows.tsx, desktop/src/{main.ts,preload.ts}, desktop/assets/defaults.json, desktop/README.md

## Tested
tsc, 268 web tests, web build. Real Electron (headless): landing → "Connected" → login opens; server down → "No connection" → login opens from the bundled files; unconfigured copy → "not set up" message; login page has no company field.
## Not tested
Windows install; the landing page on a real high-DPI screen.

# B28 — Windows desktop app (Electron), auto-update, silent printing

## What it is
A new `desktop/` package: the web app inside a Windows window, packaged as an installer. It carries its own copy of the app, so it **opens with no internet from the very first launch**. Everything offline from B25–B27 (stored price/customers, offline sign-in, outbox, drafts) works the same inside it. The web version and PWA keep working as before; one codebase, two ways to run it.

## What changes for people
- Install `Gilded-Setup-x.y.z.exe`; first screen asks for the **server address** once (checked, then remembered). Menu → *Gilded → Change server address*.
- **Receipt printer** (My settings → This device, desktop only): pick any Windows printer and receipts print with no dialog. Reports still open the print dialog.
- **Updates**: checks the company server at start and every 4 h, downloads quietly, banner "Gilded x.y.z is ready — Restart now" (installs by itself on next close otherwise). Offline = nothing happens.
- My settings → This device also shows the version, "Check for updates", and "Change server address".

## Files
New: desktop/ (package.json, tsconfig.json, README.md, src/{main,preload,updater,config,assets,cors,serverUrl}.ts, src/desktop.test.ts, assets/{setup.html,defaults.json,icon.png,icon.ico}), web/src/shared/platform/platform.ts, web/src/features/settings/DesktopRows.tsx, deploy/updates/win/{stable,beta}/.gitkeep
Changed: package.json + package-lock.json (repo root; adds the desktop workspace), .gitignore, deploy/{Caddyfile,docker-compose.yml,Dockerfile.web}, web/src/{main.tsx,shared/lib/env.ts,shared/pwa/pwa.ts,layouts/UpdateBanner.tsx,features/settings/personal.ts,features/settings/pages/MySettingsPage.tsx,features/receipt/ReceiptPage.tsx,features/accounts/pages/DailyAccountPage.tsx}
Run `npm install` at the repo root after copying. Read desktop/README.md for building and releasing.

## Decisions / deviations from the plan
- **No separate SQLite yet.** Electron's own storage (IndexedDB on disk) is not evicted like a browser's and already holds the outbox and cache, so adding SQLite now would add risk for no gain. It comes with the branch hub step, where it is needed.
- **No server change for CORS/cookies**: the desktop window adjusts the answers from *its* server only (src/cors.ts). The server stays strict for the web.
- Plain http servers work for a laptop demo / branch LAN; the app warns in its log for http over the internet.

## Tested
7 desktop unit tests (address cleaning, file serving can't escape the build folder, cookie/CORS rewriting); web tsc + 268 tests; production web build; `npm ci` for the web image without Electron.
In real Electron (Linux, headless): window opens from bundled files at app://gilded with the server **down**; sign-in call reaches a stand-in server that rejects cross-site preflights (works, error message shown); first-run setup screen rejects an unreachable address; Windows app folder packages (`electron-builder --win --dir`).
## Not tested (needs Windows)
The installer .exe itself (needs Wine here), the NSIS install/uninstall, auto-update end to end (needs two published versions), real printers (silent print), SmartScreen. First thing to try on Windows: `npm run dist -w @gold/desktop`, install, enter the server address, sign in; then put a higher version in `deploy/updates/win/stable/` and watch the banner.
