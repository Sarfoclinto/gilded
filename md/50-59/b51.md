# B51 — Offline day open/close, step 1 of 3: the server

Design: docs/OFFLINE-DAYS-DESIGN.md. **Nothing changes on screen yet.** This makes the server ready to receive openings and closings made with no internet; the screens come in B52, the branch hub in B53.

## What the server now does
For an opening or closing that arrives through the offline sync (made on a computer with no connection):
- **Never refused for a missing reason.** The person could not see the server's books. The count is recorded, the books are corrected to it as always, and every figure that does not match becomes a difference for the manager with the note "Found when the offline count reached the server." A closing then waits for sign-off like any closing with differences. The manager gets a notification.
- **Same date opened twice** (offline at the branch, and online by someone else): the first to arrive is the day. The other opening is kept as a count against it (a difference if the totals differ), and every entry made under its id (cash in/out, note exchange, its closing) joins the real day.
- **Day already closed:** the offline closing is kept as a second count against the closed day (a difference per figure that differs, with the teller's own words). Nothing is reopened, the books are not touched.
- **Waiting entries go in by themselves.** When an opening or a closing is applied (online or offline), the server tries that branch's waiting ("held") entries again, oldest first, each as the person who made it. So another computer's cash movement that arrived before its day, or the next day's opening that arrived before the previous closing, no longer needs a manager to press Try again.
- The day shows new flags in Day history: "Closed while offline", "A difference was found when the offline count arrived", "A second count arrived for this day". What the device showed the person (`basis`) is stored with the day.

**Online opening and closing are unchanged:** a count that differs still needs a written reason, a closed day is still simply closed.

## Things to know
- A teller could avoid writing a reason by counting offline. The result is a flagged difference, a pending sign-off and a manager notification, so it is visible, not hidden.
- A manager may still get "An offline entry needs review" for an entry that the server then applies by itself a moment later (the review list is then empty). I left that notice as it is; say if it is noise.
- The device must send the confirmation wording it showed (`confirmation.text`) with an offline closing. B52 does that.
- One test in 042 changed on purpose: a held movement is now applied by the server when its day arrives, instead of by a manager's retry.
