# B53 — Offline day open/close, step 3 of 3: the branch hub

Needs B51 and B52. This finishes the offline-days design (docs/OFFLINE-DAYS-DESIGN.md). No database change, no C# change. **The desktop app must be released again** (the hub lives in it), and the hub computer and the other computers of a branch should all take the update.

## What changes in a branch with several computers
- **One open day per branch, also with no internet.** Opening and closing go through the hub like notes do. When one computer opens (or closes) the day, the others show it within a few seconds.
- **Two people try at once:** the second is told "The day was just opened on another computer" / "This day was just closed on another computer" and nothing is saved for them.
- **Hub away** (switched off, cable out): the computer saves alone as before and copies its opening/closing to the hub when it is back. If two computers each opened the same date alone, the hub treats it as one day (the same rule as the server), and the server keeps the second count.
- **A computer with no connection counts from a colleague's.** If one computer in the branch reached the server more recently, the others now work from that server answer through the hub (before, each computer only had its own).

## A fault found and fixed on the way (affects hub branches today)
The hub never forgot an entry. It relied on the server's "already applied" list, but that list only covers the day that is open. So **from the second day a hub was in use, yesterday's payouts were taken off today's drawer again** on the hub and on the other computers: the drawer shown would be too low, and notes could be refused that are really there. It was not seen in testing because every hub test so far was on a single day.
Fixed:
- when the hub is given a server answer, everything that answer lists is marked "the server has it" for good;
- each computer also tells the hub when the server has taken its entries, together with the server answer that includes them, which covers entries applied on a day that is already over;
- an entry stops counting only together with a server answer that includes it, so the drawer never jumps.
A simulation of several days with the connection coming and going (5 seeded runs, 250 steps each, 3 computers) checks after every step that the hub shows the drawer that is really there.

## Under the hood
- core-ts `drawer.ts`: one step function used by the screens and the hub (so they cannot disagree); `replayLog` follows openings and closings; `admit` judges them (`day-open`, `day-not-open`); the view lists merged day ids (`aliases`).
- desktop hub: log entries carry `confirmedAsOf` (an older log file gains the column when opened); `active()`, `state()`, `confirm()`; two new requests between computers (`GET /v1/state`, `POST /v1/confirm`); a badly formed opening/closing is refused at the door.
- web: openings/closings are shared with the hub; the other computers' entries are taken in the hub's order (it matters now that days change); the hub's picture replaces the last one on each poll; a new computer talking to an old hub falls back to the old request.

## How to test by hand (two computers in one branch, hub set up)
1. Both online, day open. Buy on A and on B: each drawer shows the other's payout within a few seconds (as before).
2. Unplug the internet (keep the two computers on the same network). Close the day on A. Within a few seconds B's drawer shows the day closed. Try to close on B at the same moment as A if you can: one of them is told it was just closed on another computer.
3. Next day (or change both dates): open on B. A shows it open. Buy on both; the notes are shared as usual.
4. Plug the internet in. Both queues empty. Day history shows yesterday closed and today open, each once.
5. **The fixed fault:** with a hub in use, work a day, close it, open the next day, and check the drawer total on every computer equals the opening count before any purchase (before this update it would show lower by yesterday's payouts).
6. Switch the hub computer off, open the day on a member (it says "Not shared"), switch the hub on: the other computers show the day open.

## Limits (to know)
- An entry the server kept for a manager's review stays counted by the hub until the server applies it; if a manager applies it on a later day than it was made, the hub may count it once more until the next day's count corrects it. Rare; say if you want it closed.
- The hub's log file keeps every entry (it only stops counting them). It grows slowly; trimming it can be added later.
