# B50 — Managers are told when the drawer ran short at a branch hub; calculator no longer crumpled in the tools panel

## The problem
Computers in a branch share one cash drawer through the branch hub. If a computer saves while it cannot reach the hub, and the hub later finds the drawer did not hold the notes for that entry, the hub records it anyway ("reality wins", nothing is dropped) and marks it short. Until now nobody was told.

## What changes
- When the hub says an entry was recorded short, the computer that saved it tells the server. The branch's managers (people who may review differences at that branch) get a notification: "The drawer ran short at Tarkwa's hub (GHS 800)", with the missing notes, linking to the drawer history.
- One notice per entry, even if the computer reports twice (a retry, a restart). The report is kept on the computer until the server has it, so a branch with no internet tells its managers as soon as it is back.
- Nothing is refused or changed. The entry itself reaches the server the usual way; this only adds the notice and a small record.
- The person who made the entry is not notified (they know); a manager of another branch is not notified.

## Also in B50: the Focus calculator in the tools panel
In the narrow tools panel (on a big screen) the Input and Results cards were placed side by side because the layout looked at the screen width, not at the room the calculator had, so everything was squeezed. Now the cards sit side by side only when the calculator itself has room (about 768 px or more, a CSS container query) and stack otherwise, as on a phone. In a narrow space the small captions ("details of the gold", "update as you type") are hidden so the Classic | Focus switch keeps its shape. Checked in a browser at 430 px wide (stacked, tidy) and 1000 px wide (side by side, as before).
Changed: web/src/features/transactions/focus/FocusItems.tsx, web/src/features/transactions/focus/LayoutSwitch.tsx. New Transaction uses the same code, so check it still looks right on a big screen.

## How to test by hand (two computers, one hub; or the hub computer alone)
1. On a member computer, disconnect it from the hub (turn the hub off, or unplug the network between them), then save a payout that uses notes the other computer has already used (e.g. the other computer takes the last 100s meanwhile).
2. Reconnect. Within a few seconds the member copies its entry to the hub; the hub flags it short.
3. Sign in as a manager of that branch on another device: the bell shows "The drawer ran short at <branch>'s hub (GHS …)". Tapping it opens the drawer history.
4. Repeat the same step 2 (restart the member app): no second notice.
5. Turn off the member's internet before step 2, then turn it on: the notice arrives then.
