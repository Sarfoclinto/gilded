# B63: evidence rules (v1.15.0)

Nothing here blocks a purchase, a loan, a day or a transfer. The only rule that refuses anything is the company's own "camera only" switch.

## What changed
- **Camera pictures only** (Settings → Photos, off by default): the library button, drop and paste disappear, and the server refuses `source: library` with `CAMERA_ONLY`. The phone's own camera app still works. Profile pictures are exempt.
- **Same picture used twice**: the phone fingerprints the original file before shrinking and stamping it. When a second record gets a picture from the same file, it shows "Used before" in the library and viewer, reviewers get a notification ("The same picture was used on two records") and the audit trail gets `attachment.reused`. The first use is never marked. This catches the same file picked twice; it does not catch a different photo of the same gold, or a screenshot of a photo.
- **Missing photos** (Photos page, new pill): closed days with no closing picture, hand-overs with no picture (last 30 days) and held gold with none (any age), each linking to its record.
- **Share**: a Share button in the viewer opens the phone's share sheet (WhatsApp is one choice). Where the browser cannot share files it saves the picture. Customer IDs have no Share button.
- Backend: migration 0063 (setting default, fingerprints table, `attachment_json` now says `reused`, `add_attachment` wrapper, `photo_gaps`), `GET /attachments/gaps`, openapi updated.

## Not done (decisions for the company)
- **Retention and archive.** Nothing is deleted. Disk use is about 16 GB a year at five branches; we can decide a keep period later. Ghana's Data Protection Act applies to ID pictures: check retention and consent wording with the company's adviser.
- Late-photo alerts: not built. A photo arriving long after its record is not flagged; the Missing list covers pictures that never arrive.

## Tested
DB: 56 files pass (new 056: reuse marked on the second use only, one notification, replay does not notify twice, camera-only refusal). Web: tsc clean, vitest 386 pass.
## NOT tested
C# (no dotnet here), including the new unit test. The Missing list is only tested for returning a list (the test data has no closed day or released transfer), so check it with real data. Not opened in a browser: camera-only, Share, Missing and "Used before".

## How to test
1. Settings → Photos: turn on Camera pictures only; the library button is gone from the camera sheet and a library upload attempt gets "only keeps pictures taken with the camera".
2. Off again: choose the same library picture for two purchases; the second shows "Used before" and a manager gets a notification.
3. Photos → Missing photos: close a day without a photo; it appears. Add a photo from the day history; it leaves the list.
4. Open a picture on a phone, tap Share, choose WhatsApp.
