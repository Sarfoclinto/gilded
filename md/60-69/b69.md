# B69: the Tools panel redesigned; debt totals that count every debt; the branch computer no longer counts a held purchase twice (v1.19.0)

Needs the database migration (0069), the API deploy, the web deploy, **and a new desktop app release** (the branch computer's drawer logic lives in it, through core-ts). Based on `feat-workings-share` (B68).

## 1. Tools panel (web)
The panel's tabs had grown to seven and scrolled sideways. Now:
- **A tool rail down the left of the panel**, in the navy of the main menu. Each tool is an icon with a short label (Value, Notes, Customer, Cash, Closing, Market, Sheet); a gold bar marks the one in use, and the close button sits at the top. It never scrolls sideways, however many tools there are.
- **Above each tool, its name and one plain line** on what it is for (for example "Value gold beside any page. Save it as a purchase when you are ready.").
- **A small gold dot on Customer** while a customer is being worked on, so it is clear their history is one tap away.
- Same at every size: the side panel on a computer (now 440 px by default, never narrower than 360, so the rail and the tool both fit), and the bottom sheet on phones and tablets.
- Keyboard: arrow keys, Home and End move between tools; screen readers hear it as a tab list.
- Nothing changed inside the tools themselves: what you typed in the calculator and notes, and an open sheet, survive switching tools.

## 2. Debt totals (database, API, web)
**The bug:** the Home "Debts" tile and the Debts page added up the debts in the list, and the list stopped at the 100 newest. A branch with more than 100 open debts showed "Owed to us" too low, the overdue count too low, and its **oldest open debts, which are the likeliest to be overdue, did not appear at all** (and could not be searched).
**Now:**
- the figures (owed to us, we owe, overdue, gold held as security) are counted by the server over every debt (`GET /debts/summary`);
- the Open list shows every open debt (up to 1000), so nothing old drops off;
- the All list (settled included) shows the 200 newest and says so when there are more;
- the Home tile also shows how many are overdue.

## 3. The branch computer counting a held purchase twice (core, desktop, web)
**The bug (the "B53 limit"):** a purchase was not tied to a day: it came out of whichever day was open. If the server held a purchase for a manager's review, it stayed in the branch computer's log, and when the next day was opened (with a hand count that already lacked that cash) the purchase was taken out of the new day's drawer as well. The drawer shown on every computer in the branch was too low, and notes that were really there could be refused.
**Now:** a purchase and a payout record the day that was open when they were made, and they count only against that day, the same rule movements and note exchanges already had. A purchase made under an offline day id that the server later merged into the open day still counts (tested). Purchases queued before this update carry no day and count as before, so nothing already waiting changes behaviour. The day is not taken from the device's clock, so a computer with a wrong clock cannot cause cash to be missed.
The server ignores the new field (its JSON reading skips unknown fields), so no API change was needed. **What the server does when a manager applies a held purchase on a later day is unchanged**: it is applied to the day that is open then, as before.

## How to test
1. Open the Tools button on a computer and on a phone: the rail on the left, no sideways scrolling; switch tools with clicks and with the arrow keys.
2. At a branch with many debts, compare "Owed to us" with the sum of all open debts; the oldest overdue debts appear in the Open list.
3. Branch with a hub: make an offline purchase that the server will hold (for example after closing), open the next day, and check every computer's drawer equals the opening count.
