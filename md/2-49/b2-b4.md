# Frontend B2–B4 + pending-payments API: what changed and where it goes

Paths are from the repo root (`gold-valuation/`). "Next to" names a file you already have in that folder.
No new npm packages. Nothing to install.

## 0. Do this first

1. **Backend**: add the 0013 migration and the files in section 1, then run `backend/db/run-tests.sh` (should end `ALL DATABASE TESTS PASSED`), then `dotnet test`. Restart the API.
2. **Frontend**: copy the files in section 2 (and delete the `web/src/mock` folder). Then:
   ```
   cd web
   npx tsc --noEmit
   npx vitest run
   npm run dev
   ```
3. `web/.env.development` / `.env.example` no longer have `VITE_USE_MOCK`. The mock is gone. If you have a `web/.env.local`, keep only `VITE_API_URL=http://localhost:5080/api/v1`.
4. **Sign out and sign in again.** Permissions are read at login, so an old token will not show the new screens.
5. The login screen now has a **Company** field (your tenant slug, the same one the seed created). It is remembered on that browser.

## 3. What each screen does now

| Screen (menu)               | Who                                      | What to try                                                                                                                                                                                                                                                                        |
| --------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Prices** (Setup)          | manager/director publish; everyone reads | Publish the GoldBod reference price, set each branch's margin. Director can "Save and approve". A branch with no price shows a clear "not set" state, not an error.                                                                                                                |
| **Open the day**            | teller+                                  | Count notes. "Same as the books" fills the carried-over cash. A different count needs a written reason. First day of a branch has no books to compare.                                                                                                                             |
| **Close the day**           | teller+                                  | Seven figures (cash notes, top, down, value, debts owed to us, amounts we owe, unrefined gold held). Each figure that differs needs its own reason. The confirmation text comes from the server (v3) and must be ticked. Pending mobile money is shown as a warning.               |
| **Cash drawer**             | teller+                                  | Balance, "what the books hold now" (all seven figures), top-up/withdrawal.                                                                                                                                                                                                         |
| **Day history**             | teller+, manager signs                   | Expand a day to see books vs counted vs reason for every figure and the confirmation. Filter "waiting for sign-off". Approve/Reject (reject needs a reason). You cannot sign off a day you closed.                                                                                 |
| **New transaction**         | teller+                                  | Customer search by name/phone. "How is it paid?": add mobile money (from another branch), "we owe them" (needs name and phone), or "gold settles a debt" (customer must be picked from the list). Cash is whatever is left; if nothing is left in cash, no notes leave the drawer. |
| **Transaction detail**      | everyone with read                       | "How it was paid" list. Manager at the sending branch gets **Resolve** on pending mobile money.                                                                                                                                                                                    |
| **Mobile money** (Money)    | read; manager resolves                   | Two tabs: "This branch must send" and "Other branches sending for us". Resolve = "It was sent" or "It did not go through" (then say how the customer is paid instead; amounts must add up).                                                                                        |
| **Debts and loans** (Money) | read; teller+ manage                     | Owed to us / We owe. Give a loan (cash out, optional unrefined gold as security, top weight only). Repayment in cash or mobile money. Expand a row for the history.                                                                                                                |
| **Held gold** (Money)       | read; teller+ manage                     | "Refine and buy" opens New transaction already tied to that gold and customer, with a one-tap "Settle the loan". "Hand back" only works when the loan is fully paid (the server enforces this).                                                                                    |
| **Home**                    | all                                      | Tiles depend on permissions: price, drawer, days waiting for sign-off, mobile money waiting, debts, held gold.                                                                                                                                                                     |

Open day, close day, loans and repayments need a connection (they are checked against the books). Purchases and top-ups still queue offline.

## 4. Suggested walkthrough (in this order)

1. **Director**: Prices → publish a reference price, set and approve margins for both branches.
2. **Teller (Tarkwa)**: Open the day, count notes → New transaction with part cash, part mobile money (sent by Kumasi), part "we owe them" → see the "Mobile money pending" chip.
3. **Manager (Kumasi)**: Mobile money → "This branch must send" → Resolve → "It was sent". Try a second purchase and choose "It did not go through" with a cash replacement.
4. **Teller**: Debts → Give a loan with security gold → Held gold → Refine and buy → Settle the loan → check the debt is closed.
5. **Teller**: Close the day with deliberately wrong figures; check each reason box appears only for what differs.
6. **Manager**: Day history → Waiting for sign-off → Approve; try Reject without a reason; try to sign your own day as the teller who closed it.

## 5. What was and was not tested

- Checked: `tsc --noEmit` clean, 37 unit tests pass (closing rules, split-payment rules, drawer projection, menu filter), `vite build` succeeds. The real JSON produced by the SQL functions (days, closing preview, transactions with cash + mobile money + owed, debts, held gold, pending payments) was parsed with the frontend's validation schemas and matched. The one field SQL does not produce (`confirmation` on the preview) is added by the C# service, which I read to confirm.
- **Not tested**: the screens in a real browser and the C# API (I cannot run either here). Expect small layout and wording problems and report them. The API routes the screens call are the ones in `docs/openapi.yaml`.

## 6. Known limits and open questions

- A **failed mobile money part** is resolved by someone at the sending branch, so a cash replacement is entered there but comes out of the purchase branch's drawer. Is that what you want, or should the purchase branch finish the replacement? (Needs your decision.)
- What happens to goods after Kumasi receives them is still open (planned for B5 transfers).
- Loans need an open day (the cash leaves the drawer).
- Look and feel is plain on purpose, as agreed. Core flow first.
