# B7b-2: Opening balances (gold and debts at go-live)

Completes the data import: Setup → Bring in data → **3. Opening balances**. Loads what each branch holds on its go-live day.

## Run first

1. `backend/db/migrations/0021_opening_balances.sql` (new): `dotnet run --project src/GoldValuation.Api -- migrate`
2. Nothing new to install; the director already has `imports:manage`.

## Important fix inside this migration

Opening a branch's first day used to treat _any_ earlier ledger entry as "history", so a branch with opening gold or debts would have been asked to explain its first cash count as a difference. `open_day` now treats the first drawer count as the go-live count unless the branch already has a day or cash entries. (Tested: test 015 opens the first day with no explanation after opening balances.)

## How it works

- Gold sheet: `Branch, Top, Down, Value, Note`. One line per branch; it becomes the branch's go-live gold (the base for the day-closing checks). A branch can have it once.
- Debts sheet: `Branch, Name, Phone, Type, Amount, Date, Due date, Reason`. Each is a normal debt owed to the branch, repaid in the normal way. A customer needs a phone number.
- Choose the go-live date, preview both sheets, press Apply. All or nothing; sending the same batch twice changes nothing.
- Undo (Earlier imports) reverses the gold and writes the debts off, until a debt from the import has been repaid. Then fix it with a normal adjustment.
- Cash is not here: it is the first count when the branch opens its first day.
