# B48 - The website's background worker no longer swallows /updates; guide 11 fixes

## What you saw
Opening `https://app.gildedgold.org/updates/win/beta/Gilded-Setup-0.2.0.exe` in the browser showed the Gilded app's own "not found" page instead of a download. The server (Caddy) was set up correctly. The cause is the website's **service worker** (the PWA background worker): in any browser that has opened Gilded, it answers every page address with the app's page, except `/api`, `/hubs` and `/health`. `/updates` was missing from that list, so the browser never asked the server.
Installed desktop computers are not affected (the updater fetches the files directly, not in a browser tab).

## Changes
- `web/vite.config.ts`: `/updates/` added to the worker's exception list.
- `docs/deployment/11-desktop-releases.md`: the one-time server commands (create `beta`/`stable`, `chown` to `deploy`), checks done with `curl -I` or a private window, the 404 explained in the troubleshooting table.
- `CHANGELOG.md`: v1.2.1 (nothing visible for staff).

## Until it is deployed
Check the files with `curl -I https://app.gildedgold.org/updates/win/beta/latest.yml` (expect `HTTP/2 200`) or an incognito window. A browser that already has the old worker picks up the fix the next time it loads the site after the update.

## Tested / not tested
Passed here: typecheck, web tests 302. Not tested: the worker in a real browser. After you update the server, open the site once in your normal browser (it replaces the worker), then open the installer address: it should download.
