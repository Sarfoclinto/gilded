# B35 — Hub phase 5: the screens share the drawer through the hub

With B33 (hub brain) and B34 (pairing) in place, computers that are the hub, or have joined one, now share the cash drawer. Browsers and computers with no hub behave exactly as before.

## What changes for the tellers
- **Notes are reserved before a save.** When a purchase, payout, cash in/out or note exchange is saved, the hub is asked to reserve the notes first. If another computer just used them, nothing is saved and the screen says so, e.g. "Another computer just used some of those notes (short by 7 × GHS 100). Choose the notes again." The teller picks again. This is one step at the hub, so two computers cannot both get the same notes.
- **The drawer counts the other computers.** Each computer pulls what the others saved (every 4 seconds) and takes it off the balance it shows and offers notes from. "Changes not sent yet" counts only this computer's own.
- **If the hub is off or unreachable, nothing blocks.** The computer saves on its own as before (header pill: "Not shared"). What it saved is copied to the hub as soon as it is back; anything that then turns out short is recorded and flagged, never dropped (reality wins).
- **Each computer still sends its own entries to the server itself**, signed and in order, as in B31. The hub keeps the branch's order and watches the notes; it does not stand in for the server. If a computer has a connection, it also gives the hub the server's latest day state so everyone counts from the same starting point.

## Under the hood
- Hub: `submit` has a **strict** mode (record only if the drawer can cover it; otherwise nothing stored and the missing notes are returned). Manager exposes the same three calls (submit, since, snapshot) on the hub computer itself and on members, and reports "unreachable" instead of failing.
- Web: `outbox.enqueue` now returns `{ ok }` / `{ ok:false, message }`; the five save places (new purchase, pay out, cash in/out, two note-exchange screens) handle it. `hubShare.ts` (reserve + peer commands), `hubSync.ts`, `HubSync` (background pull and late copy), drawer view includes the others' commands.

# B34 — Hub phase 4: pairing, the encrypted link between computers, and the status pill

Computers in one branch can now find each other. **The drawer is not shared yet** (that is phase 5, where screens start using the hub); this step builds and proves the safe connection and the settings to set it up.

## How it works for people
- On the computer that will be the hub (usually the manager's): **My settings → This device → Shared drawer → Make this computer the hub** (needs "manage settings"). Then **Add a computer**: it shows one line, for example `192.168.1.5:47600#482913#A1B2C3D4E5F60718`.
- On each other computer: **This device → Join a hub**, type that line, **Join**. The line works once and for 10 minutes. After five wrong tries it is thrown away. A branch can have at most five computers.
- The hub lists the joined computers (last seen) and can **Remove** one at any time; that computer is turned away at once.
- A small pill in the header appears only on these computers: **Hub / Hub stopped**, **Shared / Not shared**. If the hub is off or unreachable the computer simply keeps working on its own, as before.
- "Stop being the hub" and "Leave the hub" go back to working alone. The hub's log stays on disk.

## How it is made safe
- **Encrypted** (TLS). The hub makes its own certificate once. The line it shows includes the start of the certificate's fingerprint: a joining computer checks the certificate against it before sending the code, so another device on the network pretending to be the hub is turned away, and the code is never given to it.
- **Pinned.** After joining, a computer trusts exactly that certificate and nothing else when talking to the hub. A different certificate fails the handshake, before the secret token is sent (shown as "not the hub this computer was paired with").
- **Token per computer**, long and random, only a hash kept on the hub. Who sent a command is decided by the token, not by what the sender says.
- Nothing is opened to the internet: the hub just listens on the branch network (port 47600).
