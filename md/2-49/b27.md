# B27 — PWA: the web app opens with no connection

## What changes for people
- After the **first visit with a connection**, the whole app (code, fonts, sounds, icons) is stored on the device by a service worker. Closing the browser, restarting the computer or losing the internet no longer leaves a blank page: the app opens, then the stored price/customers/sign-in (B25/B26) take over. A toast says "Gilded is stored on this device…" the first time.
- **Installable**: browsers offer "Install" (own window / home-screen icon). Also in My settings → This device → Install. Icons, name and navy theme colour included (iPhone: Share → Add to Home Screen).
- **Updates never interrupt**: a new version downloads in the background; a banner at the top says "A new version of Gilded is ready" with **Update now** / **Later**. The app checks hourly while open. Unsent purchases and drafts survive the reload.
- **Storage protection**: the app asks the browser not to delete its stored data when the disk is short; My settings → This device shows Yes / Not guaranteed.

## Deploy notes
- Serve `index.html` and `sw.js` with `Cache-Control: no-cache` (nginx: `location = /sw.js` and `/index.html`); files under /assets are hashed and can be cached for a year. Without this an old shell can linger.
- Must be served over HTTPS (or localhost) for service workers to work.
- The bundled Caddyfile (deploy/Caddyfile) already sends the no-cache headers for index.html, sw.js and the manifest (changed in this batch). The service worker never touches /api, /hubs or /health, and the app calls the API on the same site, so there is no CORS to worry about for the web build.

## Tested
